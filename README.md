# 城市排水防涝泵站运行与内涝处置管理平台

面向排水泵站台账、泵组运行、排水管网与检查井养护、水位雨量监测、内涝点处置、闸门调度与抢险队出动的一体化城市排水防涝运行管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
  泵组检修例外：期限口径、冲突校验、版本覆盖与单向流转集中在
  `src/domain/pumpmaint.ts` + `src/api/pumpmaint-service.ts`，通用 `runAction` 对该模块已停用。
- 想回到初始数据：清掉浏览器里 `drainage-pump:entries` 这一项，或调用 `resetModule(模块)`。

## 泵组检修期限口径

不再由班长各自拿捏，全部口径在泵组检修页「期限口径设置」里按检修类别维护，保存在
localStorage 的 `drainage-pump:kv` 中：

- **检修周期（天）**：同一台泵同一类别相邻两次检修的基准间隔，页面同时给出年检修次数参考（365 ÷ 周期）。
- **允许顺延天数**：计划完工日 + 顺延天数仍早于当天即判超期，列表标红并写明超期天数。
- **计划工期上限（天）**：登记时计划工期超过上限**不允许落库**，退回信息写明超了多少天。
- 同一台泵的两条在挂安排按闭区间判断时间是否叠加；后来登记的那条标「冲突待解决」，
  且任何会与在挂安排叠加的新安排都拒绝落库（区间端点相接不算叠加）。
- 检修编号 + 泵组编号是唯一一对：重复提交按最新版覆盖（新版本号续号），旧版置为归档保留，
  仅可在「旧版备查」里查看、不能再操作；列表与导出只含最新版。
- 状态单向流转：待开工 → 检修中 → 已完工，无回退动作；确认完工必须回填**完成日期**与
  **更换部件**（未更换填「无」），完成日期不得早于计划开工。
- 保存新口径后，所有在挂记录（待开工、检修中）立即按新口径重算超期标记；页面每次加载也会兜底重算。
- 种子数据结构升级时按 `drainage-pump:schema-version` 做分模块迁移，只替换受影响模块，
  其他模块的用户数据保留。
